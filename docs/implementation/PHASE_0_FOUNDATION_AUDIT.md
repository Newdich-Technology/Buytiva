# Phase 0 foundation audit

This is a partial audit, not a release approval. Evidence and requirement statuses are in [the master checklist](PHASE_0_TO_2_MASTER_CHECKLIST.md). The current layout preserves root `src`, root Prisma and both frontend applications. Fastify registration begins at `src/app.ts` and `src/apis/v1/registerRoutes.ts`; `src/server.ts` composes repositories, connects Prisma, starts the outbox poller and closes both on shutdown. The health endpoint checks process liveness only. Failure and signal tests with a live server remain missing.

The repo has numerous empty source/schema stubs; existence is not functionality. The file-length script passes locally but a full architectural dependency, query/index and all-model review is not complete. `src/app.ts` installs global rate limiting and OpenAPI; no complete production CORS, CSRF, ingress and security-header verification has been shown. Avoid making cross-origin/cookie policy assumptions without deployment origins. Configuration is in `src/configs/auth.config.ts` and `.env.example`; secret rotation, deployed secrets and browser/mobile bundle inspection need further validation. The email outbox has lease fencing but SMTP is at-least-once, not exactly-once.

The last checked GitHub CI run at `e52c4ed` passed validation and serial integration tests on disposable PostgreSQL 16. Locally the Prisma engine download could not be reached and PostgreSQL/Flutter are unavailable. There are no reviewed production migrations; `db:sync` and destructive fixtures are exclusively for a disposable DB. No production schema synchronization was performed. Production data migration and rollback strategy must reconcile Prisma generated migration SQL with the prohibition on handwritten SQL.
