# Security test report

See `SECURITY_AND_E2E_REPORT.md` for prior results and scope. This continuation identified two concrete gaps by code inspection: stale MFA on application decisions and stale procurer eligibility during order creation. The corresponding server changes and integration regressions are in `src/routes/identity/procurerApplication.route.ts`, `src/repositories/orders/order.repository.ts`, `tests/integration/identity/procurerApplication.test.ts` and `tests/integration/procurerServices/servicesApi.test.ts`. The new tests also cover mismatched currency, reversed/future payment and concurrent customer completion with persisted-state assertions. They require a disposable PostgreSQL instance and were not executed locally; do not report those cases as passing.

No public test-payment writer was added. Cross-customer, cross-procurer, privilege escalation, review manipulation, CSRF, idempotency and full concurrent transitions remain incompletely tested. Existing test payment fixture is inserted directly only into a disposable test database. No destructive production tests were run.

`tests/unit/auths/applicationReviewMfa.test.ts` verifies all four review routes reject stale MFA using a mocked principal. `tests/unit/orders/createOrderEligibility.test.ts` checks a mocked transaction denies creation when no eligible zone is found; neither mock establishes real database behavior. Recent-MFA guard now rejects missing, stale, future or invalid timestamps; `tests/unit/auths/recentMfa.test.ts` passed locally. Local full suite: **99 passed, 19 skipped, 16 TODO, 0 failed** (134 tests), with the database suites skipped.
