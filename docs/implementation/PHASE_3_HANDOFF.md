# Phase 3 financial handoff (design only)

No live payment or payout activation is included. `VerifiedOrderPayment` is currently a payment gate with no public writer, and direct test fixture insertion is only valid in an isolated database. Before integration, agree on merchant eligibility, supported Paystack products, webhook authenticity/replay handling, provider confirmation, idempotency, payment amounts/currency, reconciliation and incident operations. Provider virtual accounts are collection mechanisms, not assumed custody accounts. Do not promise custody, funds availability or enable procurer withdrawals without legal/compliance, operational and provider approval.

Design an immutable double-entry ledger with pending/available balances, refunds, disputes, reversals, payout approval and settlement reconciliation; constrain every transition transactionally and audit it. Model verified payment and reversals so an order cannot be completed or reviewed on reversed funds, and test webhook replays, ordering, conflicting events, partial/refund scenarios and concurrent completion. Roll out with a safe migration, isolated sandbox, monitoring and explicit release approvals. Phase 2 review work must not presume Phase 3 exists.
